## Findings

### B1 medium - Fence legacy reconcile-only state before reuse

- Category: `LOGIC_BUG`
- Location: [scripts/legacy-chatlog-import.py:79-81](/Users/maxhu/play/monica-rs/scripts/legacy-chatlog-import.py:79)
- Confirmation selector: `B1`

Description: `bind_reader_target` invokes the legacy target/ACK validator only when `state/raw` exists. A fresh state used only by the pre-merge `reconcile` action has `target.json` and `reconcile/raw/.../reader.sqlite3`, without `state/raw` or `chatlog-target.json`. If that reconciliation was interrupted, resuming it against another restored database takes the unconditional new-policy branch and ignores its existing physical-target marker and ACKs. The Reader consumes the first database's saved ACKs/cursors, so already committed source rows are never emitted to the second database. Its persisted per-table scan counts still include those rows, allowing business-table catalog completion despite missing records. A later independent read-only verify can detect this, but apply/reconcile itself must not certify the wrong target.

Rationale: the final merge combines the prior branch's `bind_state` format and nested reconciliation state with main's `bind_reader_target` wrapper. The old branch always called `bind_state`; main had no nested reconciliation state. The new wrapper calls the retained validator only for the main Reader folder and thereby introduces a bypass for the other supported layout. This is a valid resumable workflow and a concrete violation of the intended physical-target fence.

Evidence:

- Changed lines 79-81 place `bind_state` under the existing `elif (state/"raw").exists()` guard, while lines 82-83 create a new stable target policy unconditionally otherwise. Neither `target.json` nor `state/reconcile/raw` triggers validation.
- `bind_state` lines 42-50 already recognizes `target.json` and both Reader layouts. `main` lines 523-534 places reconciliation Reader state at `state/reconcile`, and omits the completion marker until the entire operation succeeds (line 546).
- Reader `pending()` consumes an existing ACK and advances local state without emitting the page; immutable `apply()` accumulates `scan_counts`, and `archive_tables()` trusts `scan.count_records(...)` for business-table coverage.
- Independent standard-library synthetic reproduction executed the actual reviewed binding functions (AST-loaded to avoid optional psycopg import) and actual Reader. Two contacts were scanned with LIMIT=1. The old binding was for `cluster-a`; the first page was ACKed in `state/reconcile` and execution interrupted. Calling merged `bind_reader_target` for `cluster-b` succeeded. Resume emitted only `contact:second`; `scan.count_records('contact/contact.db','contact')` returned `2`. No real database, personal data or external service was used.
- The current tests call `bind_state` directly for foreign/recreated-target checks. Their local `run(..., reconcile=True)` helper also puts the immutable Reader directly in the supplied state, rather than production's nested reconciliation folder, so they do not cover this layout/wrapper interaction.

Repair direction: when `chatlog-target.json` is absent, validate any legacy physical marker or either supported Reader layout before writing a new policy. Preserve the stable new marker's ability to reuse one state for later snapshots on the same physical target and owner. Add a focused interrupted reconcile-only upgrade regression through the production binding wrapper, with a foreign-target negative case and a same-target resume case.
