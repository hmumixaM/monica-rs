## Findings

### B1 [medium] - Migrations inherit interactive query deadlines

- Category: LOGIC_BUG
- Location: crates/monica-server/src/main.rs:122-125
- Confirmation selector: B1

Description: Every CLI command first initializes the request/background/control pools. Migrate then runs SQLx schema DDL on the interactive pool. That pool enforces a 10-second statement timeout and 1-second lock timeout designed for normal requests. Fresh-database DDL can legitimately exceed those limits on the supported NAS storage, so installation fails before the server starts.

Rationale: The branch introduces the bounded request pools and routes migration through their interactive connection. Schema administration is a separate, explicit CLI operation. It needs a separately bounded connection; weakening ordinary request budgets would change unrelated runtime behavior.

Evidence:

- `main.rs:122-125` constructs `DatabasePools` and dispatches `Command::Migrate` to `pools.interactive`.
- `resources.rs:69-85` installs session statement/lock limits; the interactive statement limit is **10000 ms**, not the 2-second readiness endpoint timeout.
- Actual isolated NAS PostgreSQL log `.local-validation/acceptance-2026-11-12/monica-rs-final-a08bdc8e-pg.log` at `2026-11-13 09:04:43 UTC` reports `canceling statement due to statement timeout` on initial `CREATE TABLE IF NOT EXISTS _sqlx_migrations`. Authenticated psycopg readiness already passed. Slow checkpoint fsync is separately observable in this same new test instance.
- This is not an existing production lock or database. The test has only newly generated synthetic state and is cleaned by its owner.
