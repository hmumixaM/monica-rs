### B1 [medium] - Copy ownership blocks archive readers

- Category: `LOGIC_BUG`
- Location: [scripts/nas-migration-copy.py:68-72](/Users/maxhu/play/monica-rs/scripts/nas-migration-copy.py:68)
- Confirmation selector: `B1`

Description: 复制控制器将新数据根、快照层和具体目的目录改为 root:root、0700。随后下载器以普通 SSH 用户执行 Python，无法遍历这些路径；同样，运行镜像 UID 10001 无法遍历只读挂载内的快照根。按新增工具提供的默认权限契约，复制成功后下载或原始文件读取会失败。

Rationale: 新增复制器显式设定这些权限，而新增下载器没有 sudo 或受控读取入口，Compose 也没有为运行容器设置匹配权限。

Evidence:

- scripts/nas-migration-copy.py:68-69 对 root、snapshots、provider根、destination、migration执行 chown(0,0) 和 chmod(0700)。
- scripts/nas-migration-download.py:38-46 以非 sudo SSH Python 读取 migration/copy-status.json 和账本；:73-77 同样读取快照文件。
- infra/Dockerfile:27 USER monica（UID 10001）；infra/nas.compose.yaml 将 snapshots/monica-next 挂到 /data/archive:ro。
- 建议定义明确读取身份/组或受限 sudo 导出入口，并验证下载用户和服务 UID 可遍历所需目录。此处未读取实际 NAS ACL。
