## Architecture, security and change assessment

The migration design otherwise follows the separate-installation boundary: four source connections are read-only/local; target checks prevent an identical source DB and an unrelated populated business target; source row fingerprints and table classification fail closed; page writes and SQL checkpoints commit together. Source snapshots, historical operational records and live runtime work remain separate. Raw IDs and exact original content are retained, source facts follow current account links, and partial manual-relationship uniqueness now aligns with the API conflict target. Cookie namespace reads/writes and OAuth session lookup consistently use AppState. Saved analysis remains behind its privacy policy while provider, queue claim, dispatch and browser forwarding all gate execution.

Authenticated legacy history, issue/catalogue, content and social-version handlers use bound inputs and bounded keyset pages. Original archive reads reject traversal and symlink escape, and preserve ranged downloads. Web callers render data as text, use local validated URLs and bounded archive pages. The NAS proxy alone joins the ingress bridge; app/database stay internal and all runtime source mounts use new roots. Copy/export cancellation targets only the new labelled/tagged task; the SQLite backup pins committed WAL and releases it before offline checks. The Go helper writes independent content-addressed output and rejects unsafe roots/paths, symlinks and conflicting existing bytes.

Schema changes, the archive API contract, ownership views and the persistent checkpoint boundary are the principal review risks. The complete diff-derived coverage ledger and all file inventory are in the initial report. No other confirmed introduced production defect was identified.
