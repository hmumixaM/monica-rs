# Read and import bottleneck investigation

Starting source/main:93b07a8b93603ad26279da0b9bba9c645258bba7. User authorized general Rust read optimization focused on SQL/index/schema, periodic aggregate caches, import fixes and merge to main after review. Pagination and required returned data remain. The slow live NAS is Python; it is not modified or contacted. All measurements below use a new local socket-only PostgreSQL16 cluster with synthetic data, not a claim about NAS timings.

Reproduction:10,000 contacts,100,000 identities,20,000 posts,50,000 media links,20,000 conversations and130,000 relevant cache-version rows. Three EXPLAIN(ANALYZE,BUFFERS) executions per case, no response cache. Raw plans, inputs and medians are in `.local-validation/read-latency-2026-11-13`.

- Cache-hit validation still scans/hashes130,000 subject versions:92.706ms median before building/serving a page. Replace whole-population validation with fixed partitioned committed domain epochs, retaining scoped tokens for person pages and atomic invalidation. Avoid one global writer-lock row.
- Timeline attachment lookup filters media_links by entity_id alone, but its primary key starts with entity_type. The global feed executes50 whole-table scans and takes105.248ms. Add the actual entity-leading access index; preserve all existing media/metadata/filter/cursor behavior.
- Person identities filter profile_id without an index:11.153ms to scan100,000 rows for10 current identities. Add a partial profile-leading index matching current-status reads.
- Global conversation ordering uses DESC NULLS LAST; existing index is profile-leading with different null ordering. A20,000-row scan/sort costs3.273ms and grows with population. Match global and per-person feed ordering. Match existing timeline/page-post null/direction order as well, instead of changing pagination.
- Source group membership reverse lookups have only a group-leading key. Person details need a person-leading current-membership index.
- Import recovery is exactly one lane, one at-most1000-message chunk, then unconditional1second sleep. All signed normal imports use this lane. Each turn also serially performs media recovery/expiry/orphan maintenance. Separate bounded maintenance and only back off on no progress/error; preserve pause/drain, resource admission, atomic progress and retry semantics.

Existing scoped singleflight/ETag response caching is real and already precedes page SQL. Earlier warm page results benefit from it; they do not measure uncached production reads or a large contact population. User now permits aggregate stale-while-revalidate with bounded age, but raw person/message/timeline correctness and hard identity/deletion invalidation must remain immediate.
