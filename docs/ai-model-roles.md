# 共用现有模型连接

模型设置只有一套服务地址与加密 API Key。批量处理、人物分析、写作、问 Monica 和识图使用
这套连接，分别选择已配置的模型名称。保存设置不会探测付费端点，也不启动模型任务。

| 任务 | 模型设置 |
| --- | --- |
| Memory 分片与归约、邮件分类／事件、社群和重联建议 | 批量处理 |
| 人物 Memory 最终汇总、人物建议、个人近况 | 人物分析 |
| 全局周报写作 | 写作 |
| 浏览器问 Monica | 问答；留空时优先使用写作模型 |
| 图片 OCR、已有视觉结果的动态说明 | 识图模型，沿用原有 OCR 模型设置 |

文字任务的分工留空时使用已有默认模型。新迁移 0069 不重置默认模型、密钥、隐私、
日限额或执行开关。Memory 分片缓存按实际使用的批量模型保存；切换人物汇总模型不会
无故丢弃相同批量模型的分片。队列中的旧模型配置会在调用之前核对，更新后按当前配置重建任务。
只切换批量模型也会通过正常后台队列补齐 Memory；邮件事件使用同一分工判断积压，
避免已完成的新邮件占住窗口。历史 Memory 没有独立分片模型记录时按当时的单模型解释。

人物资料输入纳入原版允许的 LinkedIn 标题／简介／所在地及微信签名／标签／地区等字段，
保留当前字段的修订 ID、来源和观察时间。聊天与私人笔记仍遵守各自已有许可。
已有资料通过每次最多 25 人的持久队列更新确定性输入，不重新扫描已导入的聊天历史，
也不触发模型调用。积压计入导入中心的“Memory 输入待补齐”。

OCR 的调度、快照和实际调用前统一核对来源：帖子／Story 的媒体及海报缩略图可选，
头像排除。聊天图片需单独允许，撤回或已删除消息不发送。聊天 OCR 不因此加入人物分析。
后台补齐跳过已有同模型的完整 OCR，包括历史导入结果；缺失、失败或已更换模型的部分才进入处理。

## Mac 和 NAS

可继续通过设置页保存配置。部署也可显式提供 `MONICA_AI_MODEL` 作为文字默认值，以及
`MONICA_AI_BATCH_MODEL`、`MONICA_AI_PERSON_MODEL`、`MONICA_AI_WRITER_MODEL`、`MONICA_AI_QA_MODEL`。
没有提供的环境变量保留数据库设置。识图沿用 `MONICA_OCR_MODEL`，也接受
`MONICA_AI_VISION_MODEL`；同时提供时前者优先。运行时的 `MONICA_AI_API_KEY` 仍可覆盖已保存密钥。
不把密钥复制到 job input、模型分工、审计或返回浏览器。

NAS 的 Rust 服务使用本项目自己的网络。`host.docker.internal` 固定映射到 Docker host gateway，
可访问同一 NAS 上已有的 LiteLLM，不加入 Monica Next 网络，也不重启 LiteLLM 或全局 Docker。
HTTP 只允许 loopback 或这个明确的主机服务别名；其他远程模型地址仍要求 HTTPS。
模型调用凭据与网页登录、MCP 密钥分别管理。

NAS 默认 `MONICA_AI_EXECUTION_ENABLED=false`、`MONICA_AI_QA_ENABLED=false`、`MONICA_OCR_ENABLED=false`。
本次现有数据导入完成前保持禁止真实调用。模型配置可预先保存，历史结果仍可查看；
导入完成并交付已审查版本后，再沿用已有模型、许可范围和日限额处理缺失或待更新内容。

## 验证范围

合成数据库与 fake provider 验证模型分工、过期队列不调用旧模型、Memory 资料及来源时间；
HTTP 回归验证分工、加密密钥和问答实际请求中的模型名称；OCR 回归验证头像排除、
聊天开关撤销后的调用前围栏、日限额及已有结果复用。不向真实模型服务发送测试数据。

完整视觉上下文进入 Memory／周报，以及超过单次窗口的全周分片，是后续独立对齐项；
本轮模型分工和来源选材不能作为它们已经完成的证据。
